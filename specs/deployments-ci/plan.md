  - Nothing deployment-related exists yet: no Dockerfile, compose file, broker configuration or CI workflow (`git ls-files` shows none).
  - Dev machine facts (2026-10-19): `bash` on PATH is the WSL launcher (default distro `docker-desktop`); Git Bash is `C:\Program Files\Git\bin\bash.exe`; `openssl` is only under `C:\Program Files\Git\usr\bin`; service registry keys grant `BUILTIN\Users` ReadKey (`Get-Acl ...\Services\W32Time`, `...\Spooler`).
- Commitments deferred to this wave: broker ACL — only the Cloud identity publishes `iiot/+/commands`, each Edge has its own credentials bound to its client id and only its own `iiot/{edgeId}/...` topics (`specs/edge-agent/plan.md:26`, D-04); Linux CI for the Linux-only file-mode check (`specs/edge-agent/plan.md:72`); a proxy in front of the Cloud (`specs/cloud-platform/plan.md:33`, D-08) — **deferred again** by the KEEP choice below.
- Minimum change: a one-command trial stack (Mosquitto TLS + ACLs, PostgreSQL, Keycloak, Cloud), generated dev secrets, the Edge packaged on the dev machine and installed as a Windows Service, CI on GitHub Actions, a Vietnamese runbook.
- Expansion signals: ~18 files across 4 small areas (broker, Cloud stack, Edge service, CI); one packet because they share the broker identities, the dev CA and the runbook.
- User decisions: **KEEP**; Edge host **Windows** (`dotnet run` or Windows Service); IdP for trials **Keycloak in compose**; CI on **push + pull request**.

## Out of scope
- Nginx/TLS reverse proxy for the Cloud API, image publishing (GHCR), production compose, production certificates and secret management (EXPAND not chosen) — the API is plain HTTP bound to `127.0.0.1` in this stack.
- Linux/systemd or container Edge; backups, monitoring, high availability; changes to Edge/Cloud behaviour other than Windows Service hosting; a local CI runner (`ci-local.sh` cut at GATE-REVIEW R-06).

## Acceptance criteria
| ID | EARS criterion | Proof |
|---|---|---|
| AC-01 | If a client connects without TLS, without valid credentials, or as another identity's client id, the broker shall not grant it that identity's session or topics. | task-01 |
| AC-02 | The broker shall allow an Edge identity to publish only `iiot/{itself}/telemetry` and `.../command-results` and to receive only `iiot/{itself}/commands`, and the Cloud identity to publish `iiot/+/commands` and receive telemetry and results; wildcard, shared and `$SYS` subscriptions and wills to foreign topics shall deliver nothing else. | task-01 |
| AC-03 | When a QoS 1 message was not acknowledged and the client reconnects with its persistent session, the broker shall deliver it again; a packet over 16 KiB shall be refused. | task-01 |
| AC-04 | When the operator generates dev secrets and starts the stack, the Cloud shall become ready and answer a Keycloak Viewer token with 200 on `GET /api/v1/edges`, no token with 401, a Viewer POST with 403 and an Operator POST with 202; the smoke test shall use its own project, secrets and Edge id. | task-02 |
| AC-05 | The repository and the images shall contain no generated secret or private key; containers shall receive only the secret files they need; `ca.key` shall never leave the secrets directory. | task-01, task-02 |
| AC-06 | When installed from a package, the Edge shall run as an automatically starting Windows Service that restarts on failure, with its program, data and registry environment writable or readable only as D-07 states; uninstalling shall remove the service. | task-03 |
| AC-07 | When code is pushed or a pull request is opened against `main`, CI shall build and run all tests on Linux and fail on any failed or skipped test. | task-04 |
